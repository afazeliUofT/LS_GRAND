# Decisive next gate

The default campaign is designed to answer whether any *algorithmic* route
survives after v1.0.

## Continue approximate latent search only when

- exactness remains intact;
- actual noisy latent rank is robustly earlier than the no-slip rank;
- a first-valid or small-list LS mode lies on a favorable paired BLER/work/time
  frontier against cached matched OSD in both dense and sparse codes; and
- target-length orbit ambiguity is absent or removable by a declared code
  screening rule.

## Continue exact LS-GRAND only when

The above holds and the exact certificate stops with low overhead without
systematically touching nearly all state queues.  v1.0 did not satisfy this.

## Stop the algorithm when

- actual noisy rank compression disappears;
- matched OSD dominates the full pre-registered LS frontier;
- acceptable BLER requires work comparable to or worse than the baseline; or
- target-length orbit ambiguity is pervasive and not screenable.

## Work still prohibited after a positive v1.1 outcome

A positive algorithmic outcome does not authorize broad hardware, multi-user,
continuous-phase, or custom-code programs.  First complete formal novelty and a
real/defensible physical-use-case gate, then compare optimized code-specific
receivers at equal net rate and energy.
